# Настройка общей базы WayMate

WayMate хранит изменяемое состояние поездки одной JSON-записью в таблице `shared_trip_state`. Для входа на устройствах используется общий аккаунт Supabase.

## Подготовка Supabase

1. В Supabase открой **SQL Editor**, вставь содержимое `setup.sql` и выполни его.
2. Открой **Authentication → Users** и создай аккаунт для поездки. Используй его логин и пароль на каждом своём устройстве.
3. В настройках Authentication отключи публичную регистрацию новых пользователей. Приложение намеренно показывает только форму входа.
4. В SQL Editor выполни запрос ниже, подставив почту созданного аккаунта. Для второго отдельного аккаунта повтори запрос с его почтой.

```sql
insert into public.shared_trip_members (user_id)
select id
from auth.users
where lower(email) = lower('your-email@example.com')
on conflict (user_id) do nothing;
```

Таблица закрыта от роли `anon`. Доступ есть только у вошедших аккаунтов, добавленных в `shared_trip_members`. Publishable key можно использовать в браузере с включёнными RLS-политиками; secret/service-role key в приложение добавлять нельзя.

## Переменные окружения

Для локального запуска значения находятся в `.env.local`, который исключён из Git.
GitHub Actions использует URL проекта и publishable key из `.github/workflows/deploy.yml`.

## Перенос данных

При первом входе устройство создаёт общую запись из своих сохранённых локальных данных. Если запись уже существует, приложение объединяет независимые добавленные позиции и расходы; при одновременном изменении одного и того же объекта используется локальная версия устройства, которое синхронизируется. После синхронизации Supabase Realtime передаёт изменения другим открытым устройствам.

Перед первым входом убедись, что исходные данные есть в браузере, который должен начать общую базу. Другие браузеры при первом входе добавят свои локальные записи в общую базу.
